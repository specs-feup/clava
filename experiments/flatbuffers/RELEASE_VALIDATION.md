## Memory

Linux JVM VmHWM is the primary peak measure. Each cell has three isolated JVMs with a 4 GiB heap and 20 parse/collect cycles, ccache disabled and removed from PATH. Retained values use post-GC samples with the same GC budget. GNU time's process-tree maximum is recorded separately and can include native children.

| Workload | Runtime | Median JVM peak, MiB | Median retained heap, MiB | Median first-to-last retained change, KiB |
| --- | --- | ---: | ---: | ---: |
| NAS LU, C99, 28,218 nodes | Eager | 561.8 | 14.91 | 36.4 |
| NAS LU | Text | 515.0 | 37.75 | 95.2 |
| NAS LU | Protobuf | 587.2 | 15.57 | 84.1 |
| Templates, C++17 | Eager | 250.5 | 15.08 | 44.5 |
| Templates | Text | 218.6 | 14.76 | 109.7 |

Eager reduces NAS retained heap substantially versus Text, but peaks 9.1% higher. On the smaller C++ workload, eager peaks 14.6% above Text and 1.4% above Protobuf, and retains 2.1% more than Text. This is a measured tradeoff, not a universal memory improvement.

All 120 eager parse/collect cycles released their ASTs and left zero mapped paths, open parser files and temporary Clang folders. Retained heap showed bounded tens-of-KiB changes across each 20-cycle run; this finite experiment cannot prove absence of long-term accumulation.

## Runtime

Matched Java parser measurements used the same 116 test identities, one 512 MiB worker, no JaCoCo, precompiled classes, ccache disabled and removed from PATH, and three observations per transport in rotated serial order. All nine observations passed. Median summed JUnit test duration was 38.016 s eager, 35.635 s Text and 31.986 s Protobuf. Eager was 6.7% slower than Text and 18.9% slower than Protobuf on this workload. Gradle wall time is recorded separately and is not added to testcase duration.

Follow-up investigation on 6 October found that these Java timings include 216 forced-GC heap samples per run, with two GC requests per sample in eager/Text and one in Protobuf. The earlier performance decision report disabled those diagnostics. A controlled run disabling explicit GC equally reduced the eager-versus-Protobuf gap to 1.751 s (6.8%). The original numbers remain production-default test-body measurements; they do not establish a reader-only regression or reproduce the earlier App timing. See [the runtime investigation](RUNTIME_REGRESSION_INVESTIGATION.md). The speed-based adoption gate remains unresolved.

The eager JS cache matrix passed all nine observations with the fixed 164-total / 158-passed / 6-pending population. Median wall times were 46.637 s cold, 42.297 s warm and 47.885 s bypass. Cold runs produced cache misses, warm runs restored direct hits, and bypass produced no cache calls.

The matched bypass JS comparison used identical 158 active test identities with ccache disabled and absent from PATH. Its single observation per transport passed: 44.319 s eager, 42.813 s Text and 39.253 s Protobuf. This is a timing snapshot, not a statistical speed claim. Four CUDA/OpenMP integrations are excluded consistently from the historical comparison workload; all four passed in the separate full Linux suite.

These runs do not establish a speed or peak-memory advantage for eager. They characterize the adoption cost while verifying the selected release, stable workload and cleanup behavior.
