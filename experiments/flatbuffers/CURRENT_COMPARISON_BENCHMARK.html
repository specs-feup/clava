Methodology and workload checks

144 accepted measured commands: 72 App observations and 72 separate uninstrumented suite commands. Three implementations, two suites, three cache states and four rounds. Each suite has the same 116 Java or 164 JS test identities, with 158 JS tests passing and six pending. These are the original comparison workloads, not every test subsequently added to production.

The original chart functions, timer boundaries and JS test-file orders are retained. Implementation order rotates each round; cache-state order rotates with it; suite order alternates. Commands run serially. Every phase has preflight checks and a separate complete-suite cache seed.

Cold starts empty. Warm restores the same saved seed before every observation. Bypass sets CCACHE_DISABLE=true and verifies zero wrapper invocations. Enabled runs unset the flag and verify real cache counters. Each implementation, suite and phase owns an independent cache. FlatBuffers also isolates entries by schema and executable hashes.

Each Java App run retains all 216 timed calls. Each JS run retains 170 timed calls and executes 130 untimed syntax-only calls. Per-build source workloads and shared-context partitions must stay consistent across modes and rounds. Cross-build source/content and ordered-option matching is checked separately. Clava-JS versus Text: 170 matching calls in 12 observations; Clava-JS versus Protobuf: 170 matching calls in 12 observations; Java parser versus Text: 207 matching calls in 12 observations; Java parser versus Protobuf: 207 matching calls in 12 observations.

The raw results retain differing generated reparses. The committed audit also reports timing over calls matched by source content and options. That subset is selected by workload identity, not speed. Text and Protobuf retain their compatible GlobalAttributes script and golden; the common C++ input and test identities stay fixed.

Java uses one 512 MiB test worker. JS retains the original default JVM heap, observed at about 7.55 GiB on this host. No coverage agent or GC-policy override enters the measurements. SHOW_EXEC_INFO=false is applied equally in isolated benchmark builds; production worktrees and the user's local selector stay unchanged.

Why the earlier conclusion changed

The earlier App cohort favored FlatBuffers in both suites. Its Java command runs also favored FlatBuffers, but JS command deltas were small: FlatBuffers was 0.155 s faster in bypass and 0.315 s cold, while Protobuf was 0.115 s faster warm.

That report measured Clava 01c6b739e and native 0a2737839. The integrated implementation adds structural and record validation, fidelity and cleanup changes. The diagnostics-off measurements now show a real remaining reversal. The exact contribution of each change has not been isolated. The pilot recommendation should have been revalidated before carrying it into production.

What matched

All 18 Java runs passed the same 116 tests. All nine JS runs passed 158 tests with six pending. Both FlatBuffers builds use identical Java fixtures, the same published RC3 producer and matching captured workloads in every round.

The Java App runs captured 216 timed calls each. Protobuf matches 207 source-and-option fingerprints; nine calls reparse different generated source. On the matching 207 calls, median App time is 25.944 / 24.037 / 25.830 seconds in the table's build order, leaving updated FlatBuffers 7.46% slower than Protobuf. This subset was selected by workload identity after capture.

All 170 timed JS App calls match across builds after checkout-path normalization. The 130 syntax-only calls per run are excluded from App time. Protobuf keeps its compatible GlobalAttributes script/golden with the shared C++ input unchanged.

Controls, revisions and limits

ccache bypass, CCACHE_DISABLE=true, ccache absent from PATH, precompiled runtimes, one serialized worker, Java 512 MiB heap and JS default heap observed at about 7.55 GiB, no coverage agent and no GC-policy override. Native assets, source snapshots and classpaths were verified. The production row includes the actual GC-request difference being fixed.

The combined patch includes the duplicate-GC fix, immutable ordered metadata construction and concurrent per-class reader cache. Three rounds on one host do not establish that the small App gains exceed noise, and do not isolate individual changes. Protobuf has a different producer and branch implementation. Validation and fidelity fixes remain enabled. Memory was not remeasured.

Measured Clava snapshots: previous f03eb45d8, Protobuf ff5e58afa, updated 09542632a. Updated specs-java-libs ae7194a7. Both FlatBuffers builds use v18.1.8_5-rc3.

The immutable map still breaks 17 legacy XStream XML persistence tests, pending its separate removal PR. PR warnings remain. No master merge or stable release was made.

Setup failures before accepted observations are documented. Java results were preserved when the first JS launch stopped on a missing log directory.
